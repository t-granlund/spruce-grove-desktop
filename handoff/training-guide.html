I · THE LINEAGEMockingbird, and how it became this

You built Mockingbird — local-first voice dictation, meeting capture, and a personal knowledge engine. Whisper on-device, push-to-talk, Obsidian vault projection, zero telemetry, Tauri 2. You built it for your own daily use and gave it away. That document — a reference implementation, freely published, forks welcomed — is the exact temperament the grove needed.

When Spruce Grove needed a desktop shell, we did not design one from scratch. We stood on your shape: thin Tauri 2 shell, no agent logic inside, everything local, nothing phones home. The difference is only what the shell drives — instead of owning a harness, it drives the groomed spruce-grove CLI. Your architecture became the reference implementation for an entire product surface. That is what "we adapted it" means: we kept everything you got right, and pointed it at the CLI.

the adaptation, stated plainly

Kept from Mockingbird: the thin-shell discipline, the local-first covenant, zero telemetry, Tauri 2, webview-without-build-step.
Changed: the tenant — instead of owning dictation and capture (your app already ships those), this shell drives the grove CLI headless and streams it.
The result: two sibling apps, one temperament. Yours is the elder.

II · THE ARCHITECTUREThin shell, four contracts

The shell owns no agent logic. Every prompt spawns the CLI in headless mode and streams its output back. Four contracts, all in src-tauri and ui/main.js:

grove_lookin
ContractHow it works
Spawn + streamgrove_send runs spruce-grove --prompt … in the chosen working dir; stdout/stderr stream to the transcript as window events. ANSI is stripped on the way in.
ResumeTurns 2+ pass --quick-resume so the conversation keeps its notes.
CancelSingle-active-run guard; one button ends the run cleanly.
Look-inLive browser panel: screenshots and actions while the agent works. Seeing is trusting.

Keep the fork's diff from growing: the shell consumes the CLI, never re-implements it. If a capability is missing, it belongs in the CLI first.

V · THE RUNBOOKRun, build, ship

cd ~/spruce-grove-desktop
npm run dev          # Tauri 2 dev shell — hot webview, live CLI
npm run build        # the bundled desktop app
npm run icon         # regenerate platform icons from assets/source-icon.png

Models (Synthetic.new subscribers): run /onboard-synthetic inside the grove once — it stores your API key in the shared credential store, installs the rotation-safe alias family (syn:large:text driving seat, syn:small:text fan-out, syn:large:vision / syn:small:vision for image work, all tagged supports_vision), and points the main model at the driving seat. Verify with /onboard-synthetic check.

Prerequisite: the groomed CLI resolves on PATH (spruce-grove — install with uv tool install spruce-grove). The sidebar shows the resolved version; if it reads cli: … forever, the CLI is not resolving. The working dir you choose is the drawer the agent works in — it cannot wander outside it.

The tests: tests/ at the repo root covers the shell contracts. Run them after any UI change that touches ids or events.
